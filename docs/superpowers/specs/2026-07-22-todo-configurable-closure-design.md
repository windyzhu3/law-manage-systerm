# Todo Engine 阶段一业务可配置闭环设计

**日期：** 2026-07-22  
**基线：** `runtime/startup-wiring-fix` / `25b75c71`  
**前置设计：** `2026-07-20-todo-engine-configuration-center-design.md`

## 1. 目标与完成定义

本阶段不扩展新的 Todo 运行时能力，集中补齐业务管理员完成“选择事件 → 配置触发条件 → 配置完成条件 → 选择业务对象 → 模拟 → 发布”所需的配置资源、引导式界面和自动化验收。

只有同时满足以下条件才算完成：

1. 所有启用事件都有非空、可解析、至少包含一个业务字段的 Payload Schema。
2. 事件目录具备列表、详情、创建新版本、编辑草稿、启停、Schema 字段维护、示例 Payload 和引用关系查看能力。
3. 校验器目录有面向管理员的只读治理页，展示编码、中文名称、适用对象、参数说明、来源、状态和引用关系；技术实现仍由 Java SPI 注册，界面不允许任意类名或脚本执行。
4. DoD 高频规则使用简易模式完成，普通用户不输入 JSON、字段编码、材料编码或 Java 类名；高级模式保留兼容能力。
5. LEAD、CUSTOMER、CONTRACT、CASE、MATTER 均能搜索真实业务对象；无真实数据时可选择明确标识的只读示例对象，空状态能区分无数据、无权限和目录不可用。
6. 模拟页面根据事件 Schema 生成表单，展示选中对象摘要，并按规则匹配、Owner、SLA、DoD、路由和待办预览顺序返回结果。
7. 新配置管理员可在 10 分钟内，不输入原始 JSON，完成一条高频规则的配置、模拟和发布。
8. 后端单元/集成测试、真实 MySQL Flyway、前端契约、生产构建和 Chrome E2E 全部通过。

## 2. 现状差距

- 36 个启用事件的 `payload_schema_json` 均没有 `properties`，触发条件字段下拉必然为空。
- 事件和校验器只有查询目录，没有管理/治理页面和稳定的展示元数据。
- 校验器来自 Java Bean 注册，只有编码、类名、描述，缺少适用对象和参数 Schema。
- DoD 编辑器把字段键、材料编码、验证器编码和 JSON 结构直接暴露给业务用户。
- 业务对象目录后端已覆盖五类对象，但演示库只有 LEAD 数据；MATTER 等类型没有对象时页面只显示空下拉。
- 模拟页面没有示例对象、空状态诊断和完整的 Schema 驱动表单。

## 3. 方案选择

### 方案 A：数据库元数据注册表 + 代码能力目录（采用）

- 事件、Payload Schema、字段展示元数据、示例 Payload 和状态由数据库版本化管理。
- 业务校验器继续由受信任 Java SPI 注册，数据库只保存中文元数据、参数 Schema、状态覆盖和使用说明。
- 业务对象通过现有数据权限目录读取；没有真实对象时由独立示例目录返回不可写示例。

优点是安全边界清晰、发布版本可审计、前端可完全由元数据驱动，并保持现有运行时兼容。

### 方案 B：全部使用字典表

实施快，但无法表达嵌套 Schema、字段类型、参数约束和版本，不采用。

### 方案 C：允许管理员上传脚本或类名扩展校验器

灵活但引入任意代码执行、版本和审计风险，不采用。

## 4. 架构与数据流

```text
事件资源中心
  ├─ 事件版本与状态
  ├─ Payload JSON Schema
  ├─ 字段中文元数据/字典来源/运算符
  └─ 示例 Payload
          ↓
触发条件构建器 ──→ 类型化字段与运算符
          ↓
DoD 简易模式 ──→ 字段/材料/校验器目录
          ↓
业务对象目录 ──→ 真实对象或只读示例对象
          ↓
只读模拟 ──→ 命中/Owner/SLA/DoD/路由/卡片预览
          ↓
发布预检 ──→ 阻止空 Schema、无效引用和未验证定义
```

运行时继续以 `todo_event_catalog`、不可变模板版本和现有编译器为事实来源，不建立第二套事件事实。

## 5. 后端设计

### 5.1 事件目录

扩展 `todo_event_catalog`：

- `event_name`、`description`、`source_module`
- 复用现有 `sample_payload_json`
- `schema_status`：`INCOMPLETE`、`READY`
- `version`、更新审计字段

事件创建采用“新事件 v1”或“已有事件创建下一版本”；ACTIVE 版本不可原地改变 Schema，只能创建草稿版本。激活前校验 Schema、示例和业务对象类型。

### 5.2 Payload 字段模型

JSON Schema 是唯一机器事实。前端字段设计器维护：

- `properties.<field>.type`
- `title`、`description`
- `x-dict-type`、`x-operators`
- `x-sensitive`、`x-example`
- `required`

嵌套对象允许两层；数组只允许声明元素类型，不在阶段一提供任意递归设计器。

### 5.3 校验器治理目录

新增 `todo_validator_metadata`，以 `validator_code` 关联 Java SPI：

- 中文名称、说明、适用业务类型
- 参数 JSON Schema、示例参数
- 状态、版本、更新审计

只有运行时已注册且元数据启用的校验器可被新 DoD 选择。移除 Java Bean 不删除历史元数据，但状态显示为 `UNAVAILABLE` 并阻止新发布。

### 5.4 配置字段和材料目录

新增统一只读资源接口，按业务类型返回：

- 可用于 DoD 的业务字段；
- 材料类型字典；
- 可用校验器；
- 高频 DoD 配方。

高频配方由迁移初始化，内容仍编译为现有 `todo_dod_rule` JSON 字段。

### 5.5 业务对象与示例对象

保留现有 actor-scoped SQL 目录。新增示例目录，示例对象使用负数 ID 并显式返回 `sample=true`，只允许模拟接口使用，任何运行时创建/动作接口拒绝示例 ID。

目录响应附带 `source`、`emptyReason` 和 `canUseSample`，页面不得把无权限伪装成无数据。

## 6. 前端设计

### 6.1 配置资源中心

在 Todo Engine 下新增“配置资源”菜单，包含：

- 事件目录：列表 + 右侧详情/编辑抽屉 + Schema 字段设计器；
- 校验器目录：治理详情、参数和引用关系；
- 业务字段/材料：按业务类型查看可用项和来源。

触发编辑器、DoD 编辑器和模拟页提供“管理资源”跳转，并在返回后刷新目录。

### 6.2 触发条件

字段下拉显示“中文名（字段路径）”，按类型限制运算符和值控件；空 Schema 显示可执行的错误提示并禁止保存，不再只显示“无数据”。

### 6.3 DoD 简易模式

默认展示四组自然语言配置：必填字段、必备材料、条件要求、服务校验。用户从目录多选，系统生成现有规则 JSON。高级模式折叠在底部并标明仅供实施人员使用。

### 6.4 模拟工作区

采用左右双栏：左侧事件、模板、对象、Schema 表单；右侧分步结果。对象下拉支持远程搜索、最近对象和示例对象，选中后展示编号、名称、类型和来源。

## 7. 错误、安全与审计

- 事件目录和元数据写入使用独立权限 `todo:resource:*`、`actionId` 和乐观锁。
- ACTIVE 事件 Schema 不可原地修改；创建新版本不会影响历史待办。
- 示例对象仅用于模拟，禁止进入待办实例、关系和业务写接口。
- 发布预检新增稳定错误码：空 Schema、字段引用失效、校验器不可用、样例不匹配 Schema。
- 事件、校验器元数据和配方修改记录审计动作及前后版本。

## 8. 测试

- Schema 解析、字段扁平化、类型运算符和示例校验单元测试。
- 事件版本、启停、引用保护和乐观锁服务测试。
- 校验器注册/元数据可用性、DoD 编译和失效引用测试。
- 五类业务对象真实目录与示例对象隔离测试。
- 真实 MySQL 验证 36 个 ACTIVE 事件全部 `READY` 且存在字段。
- Chrome E2E 覆盖事件维护、触发条件、简易 DoD、示例对象模拟和发布。
