# 线索待办模板路由与事件治理修复设计

## 1. 背景与目标

当前线索待办配置中心存在三类相互关联的问题：

1. TD-001 已发布版本引用历史已发布的下游版本，页面却按“当前最新版本”校验并显示裸 ID；
2. TD-001 的“未接通”结果被可视化结果目录错误建模为立即创建 TD-003，与生产调度契约冲突；
3. TD-002 草稿可选择不兼容事件，事件字段目录又把技术字段和未治理字段作为普通业务字段暴露。

本轮目标是在不修改已发布不可变定义、不破坏当前激活入口的前提下，恢复线索模板配置、发布和运行时的一致性，并让业务人员只能看到有意义、可选择的字段。

## 2. 已确认的业务契约

### 2.1 模板与入口事件

| 模板 | 允许的入口事件 |
|---|---|
| TD-001 首联待办 | `LEAD_ASSIGNED` |
| TD-002 疑似无效主管复核 | `LEAD_SUSPECT_INVALID_MARKED` |
| TD-003 无法联系重试 | `LEAD_RETRY_WINDOW_DUE` |
| TD-004 5天实质进展 | `LEAD_FIRST_CONTACT_VALID` |

这四个模板属于受治理模板。普通用户不能把它们切换到其他 LEAD 事件；后端保存和发布接口必须执行同一兼容性校验，不能只依赖前端限制。

### 2.2 TD-001 三个业务结果

```text
VALID
  -> 创建当前协调发布包选定的 TD-004

SUSPECT_INVALID
  -> 创建当前协调发布包选定的 TD-002

UNREACHABLE
  -> 结束当前图路由
  -> TD-001 完成处理器建立重试计划
  -> 到期调度器发布 LEAD_RETRY_WINDOW_DUE
  -> 事件入口创建当前协调发布包选定的 TD-003
```

TD-001 图中不得包含 TD-003 TASK 节点或 `UNREACHABLE -> TD-003` 普通图转换。重复调度不得产生第二张相同窗口的 TD-003。

## 3. 版本与生命周期治理

### 3.1 历史已发布版本

查看已发布版本时，路由目标只需满足：

- 目标版本存在；
- 状态为 `PUBLISHED`；
- 业务类型一致；
- 模板编码与保存的 `targetTemplateCode` 一致。

下游模板发布新版本不能让历史定义变成 `TODO_ROUTING_TARGET_VERSION_INVALID`。页面必须加载定义实际引用的历史目标并显示“模板名称 · vN · 历史已发布”，不能显示裸版本 ID。

### 3.2 新草稿和协调发布候选

新草稿的推荐路由使用本次协调发布选定的版本，而不是隐式读取全局 `current_version` 后直接覆盖历史定义。协调发布预检校验以下关系：

- TD-001 的即时目标只包含选定的 TD-002 和 TD-004；
- TD-001 的 TASK 节点包含自身、TD-002、TD-004 和误判后重开的自身节点，不包含 TD-003；
- TD-003 作为调度依赖单独锁定，并校验其 `CONNECTED -> TD-004`；
- TD-004 校验其自循环计划能力；
- 四个版本的模拟证据必须与各自定义哈希一致。

### 3.3 状态展示

模板页面分别展示：

- 当前查看版本；
- 最新已发布版本；
- 当前激活入口版本；
- 是否需要新建草稿并重绑定协调发布版本。

“已配置”“已发布”和“运行中”不能合并成一个状态。

## 4. 安全修复既有数据

已发布版本保持不可变，不直接更新 TD-001 v88、TD-002 v80、TD-003 v94 或 TD-004 v95。

使用新的前向 Flyway Java 迁移完成数据治理：

1. 保留当前激活入口，不在迁移中自动切换生产触发规则；
2. 将错误 TD-002 v93 草稿标记为 `RETIRED`，保留审计记录；
3. 从 TD-002 当前已发布版本和标准资源创建新的规范草稿，事件固定为 `LEAD_SUSPECT_INVALID_MARKED`；
4. 从 TD-001 标准定义创建新的规范草稿，绑定当前已发布 TD-002、TD-004，未接通路由为 `END`；
5. 草稿的定义哈希、验证报告和模拟证据从零开始，不能继承旧草稿通过状态；
6. 迁移可重复执行，第二次执行不得再创建草稿或改变激活入口。

迁移只负责准备可审查草稿，不自动发布、不自动激活。

## 5. 事件和字段治理

### 5.1 模板事件兼容性

新增单一后端策略 `TodoTemplateEventPolicy`：

- `allowedEventTypes(templateCode)` 返回受治理模板允许事件；
- `validate(templateCode, eventType, payloadVersion)` 返回稳定错误码 `TODO_TEMPLATE_EVENT_INCOMPATIBLE`；
- 配置旅程资源返回推荐事件和是否锁定；
- 草稿保存、编译、发布预检均复用该策略。

### 5.2 可选择字段白名单

事件字段资源必须同时读取：

- `owner_field_paths_json`；
- `condition_field_paths_json`；
- `default_value_field_paths_json`；
- Schema 中的语义、选项来源、字典和只读上下文标记。

前端按用途过滤：

- 触发条件：只显示该事件版本 `conditionEligible=true` 的字段；
- 负责人：只显示 `ownerEligible=true` 的人员字段；
- 业务展示：显示有业务名称的上下文字段；
- 技术字段：`schemaVersion`、系统流水 ID、计数器默认隐藏，只在技术详情中展示。

事件本身已经足以触发时，触发条件步骤显示“无需附加条件”，不暴露技术字段供二次筛选。

### 5.3 Schema 业务可用性

`schema_status=READY` 不再单独代表业务可配置。业务可用字段至少需要：

- 中文或受治理名称；
- 业务说明；
- ID、编码、字典字段具有语义类型；
- 需要选择的字段具有 `optionSource` 或 `dictType`；
- 技术字段被标记为只读上下文。

需要补齐的七个事件：

- `LEAD_FIRST_CONTACT_UNREACHABLE`
- `LEAD_INVALID_REVIEW_CONFIRMED`
- `LEAD_INVALID_REVIEW_MISJUDGED`
- `LEAD_MOVED_TO_DEAD_POOL`
- `LEAD_RETRY_CONNECTED`
- `LEAD_RETRY_EXHAUSTED`
- `LEAD_TAG_CONFIRMED`

事件资源接口返回 `configurationReady` 和结构化问题列表。缺少业务治理的事件不能用于新模板，但仍可供运行时消费和技术审计。

## 6. 前端行为

1. TD-001～TD-004 第一步展示推荐事件，受治理模板不可误选其他事件；
2. 打开 TD-002 时展示新的规范草稿，不再打开错误 v93；
3. 历史路由目标显示模板中文名、编码、版本号和历史状态；
4. 新草稿路由只提供本次业务结果允许的目标，不提供任意 LEAD 模板；
5. 未接通结果显示“结束当前待办并建立重试计划”，不显示 TD-003 版本下拉；
6. 事件字段按“业务上下文、负责人候选、技术详情”分组，基础配置不出现“业务字段”占位或裸 ID。

## 7. 错误处理

新增或稳定以下错误码：

```text
TODO_TEMPLATE_EVENT_INCOMPATIBLE
TODO_ROUTING_TARGET_REFERENCE_INVALID
TODO_ROUTING_RELEASE_BINDING_MISMATCH
TODO_EVENT_FIELD_GOVERNANCE_INCOMPLETE
```

`TODO_ROUTING_TARGET_VERSION_INVALID` 仅用于新候选引用不符合所选协调发布版本，不用于历史已发布定义的只读查看。

## 8. 测试与验收

### 8.1 单元测试

- 历史已发布目标仍存在时通过引用校验；
- 新草稿目标与协调发布候选不一致时阻塞；
- TD-001 未接通结果为 `END`，图中没有 TD-003 TASK；
- TD-001 有效和疑似无效分别锁定 TD-004、TD-002；
- TD-002 拒绝 `LEAD_FIRST_CONTACT_UNREACHABLE`；
- 字段目录按事件版本和用途白名单过滤。

### 8.2 MySQL 集成测试

- 前向迁移退役错误 v93 并创建唯一规范 TD-002 草稿；
- 创建唯一规范 TD-001 草稿且不改变激活入口；
- 第二次迁移不重复创建数据；
- 七个事件的业务字段治理通过目录质量检查。

### 8.3 运行时集成测试

- 完成 TD-001 `UNREACHABLE` 后立即不存在 TD-003；
- 到期物化后只产生一张 TD-003；
- 重复扫描不增加 TD-003；
- 完成 `VALID`、`SUSPECT_INVALID` 仍分别产生正确后续待办。

### 8.4 前端和浏览器验收

- TD-001 历史目标不显示 `79`、`89` 裸值；
- TD-001 未接通不显示下一模板选择器；
- TD-002 第一事件为“疑似无效已标记”；
- 基础配置中不存在“业务字段”、`schemaVersion`、`planId` 等技术选项；
- 模板列表同时显示最新已发布与当前激活版本；
- 后端测试、前端契约、生产构建和真实 Chrome 流程全部通过。

## 9. 非目标

- 不在本轮自动发布或自动激活新草稿；
- 不改变 TD-005 之后的线索阶段；
- 不重构整个 Todo Engine；
- 不删除历史版本、动作日志或模拟证据；
- 不升级 Vue、Element UI 或 RuoYi 基础框架。
