# Todo Engine 流程配置中心重建设计

**日期：** 2026-07-20  
**目标分支：** `v0.2-Foundation`  
**事实基线：** `fb3753820d0f80b24a04494cbaf997744f65fa62`  
**视觉依据：** 用户提供的 7 张流程配置中心截图  

## 1. 目标

移除当前 `todo/config/index.vue` 中以标签页承载的 Foundation 治理内容，按照参考截图重建面向业务管理员的 Todo Engine 流程配置中心。新中心提供独立菜单、完整规则管理、统一右侧抽屉操作、模板串联配置、模拟测试和发布记录，并复用现有 Todo Engine 的事件、Owner、DoD、SLA、路由、版本、预检和发布能力。

完成后的配置中心必须满足：

1. 提供待办模板、触发规则、SLA 规则、完成条件、模拟测试和发布记录六个独立页面。
2. 新建、编辑、查看、复制、启停、测试、发布和版本比较等操作均在右侧抽屉完成，不使用新增弹窗或独立编辑路由。
3. 新建和编辑待办模板时，可在一个宽抽屉中串联基本信息、触发事件、负责人、SLA、DoD、下一步规则、预览测试和版本记录。
4. 固定业务选项通过 Flyway 初始化到字典表，由前端字典组件和后端字典服务读取，不在 Java 或 Vue 中维护展示枚举。
5. 已发布版本不可修改；发布时保存所引用规则的完整快照，历史待办继续使用原版本快照。
6. 保留 Foundation 后端治理、证据和发布门禁，不在新的流程配置中心展示这些治理页面，也不删除对应数据与接口。

## 2. 方案选择

采用“前端信息架构重建、现有引擎复用、SLA/DoD 规则独立化”的方案。

- 不采用仅拆分标签页的方案，因为现有 SLA 和 DoD 只作为模板 JSON 片段存在，无法形成截图要求的可复用规则库、绑定统计和独立启停管理。
- 不重写 Todo Engine 核心模型，因为现有模板版本、事件目录、Owner 解析、路由、模拟、幂等、审计和发布门禁已经具备可复用能力。
- 新增独立 SLA、DoD 规则实体及模板绑定关系；发布时仍编译为现有不可变模板版本定义，从而保持运行时兼容。

## 3. 信息架构与菜单

### 3.1 菜单结构

父菜单保留为 `Todo Engine`，子菜单按以下顺序由 Flyway 初始化：

| 顺序 | 菜单 | 路由 | 页面组件 | 查看权限 |
|---:|---|---|---|---|
| 1 | 待办模板 | `todo-template` | `todo/config/template/index` | `todo:template:list` |
| 2 | 触发规则 | `todo-trigger-rule` | `todo/config/trigger/index` | `todo:trigger:list` |
| 3 | SLA规则 | `todo-sla-rule` | `todo/config/sla/index` | `todo:sla-rule:list` |
| 4 | 完成条件 | `todo-dod-rule` | `todo/config/dod/index` | `todo:dod-rule:list` |
| 5 | 模拟测试 | `todo-simulation` | `todo/config/simulation/index` | `todo:simulation:list` |
| 6 | 发布记录 | `todo-release-record` | `todo/config/release/index` | `todo:release:list` |

原 `流程配置中心` 单菜单调整为上述父子菜单结构。旧组件路径不再进入主菜单。Foundation 准入接口及发布守卫保留，后续可由独立治理入口消费。

### 3.2 按钮权限

每个页面至少区分查看、创建、编辑、复制、启停、测试和发布权限。菜单迁移必须幂等，不重复创建既有权限；既有 `todo:definition:*` 权限保留作为兼容权限，并映射到新页面的必要操作。

## 4. 公共页面结构

六个页面沿用当前 RuoYi Vue 2、Element UI 和业务模块的布局习惯：

1. 页面标题与简短说明。
2. 3～4 个指标卡，展示总量、启用量、当日操作和异常量。
3. 白色筛选卡，包含字典筛选、关键字、查询、重置和主要新增按钮。
4. 白色表格卡，使用现有 `el-table`、`pagination`、`dict-tag` 和权限指令。
5. 选中表格行后打开右侧详情抽屉；新增和编辑也复用相同抽屉容器。
6. 抽屉宽度按内容分为 520px、720px 和 78% 三档；模板编辑抽屉使用 78%，其余规则使用 620～720px。
7. 抽屉底部操作区固定，关闭前对未保存内容进行确认。

指标卡、筛选卡、列表卡、抽屉标题、状态标签和空状态抽成配置中心公共组件，避免六个页面重复实现。

## 5. 页面设计

### 5.1 待办模板列表

对应参考图 1。

列表字段：模板名称、模板编码、业务阶段、业务对象、触发事件、负责人摘要、发布状态、当前版本、更新时间和操作。

筛选条件：业务阶段、业务对象、模板类型、发布状态、关键字。主要操作包括新建模板、导入模板；行操作包括查看、编辑、复制、模拟测试、发布新版本、启停和查看发布记录。

右侧详情抽屉展示触发事件、负责人规则、SLA、DoD、下一步规则、待办卡片预览和版本摘要。所有摘要来自后端聚合视图，不在前端拼接业务语义。

### 5.2 新建/编辑待办模板抽屉

对应参考图 2，但遵循用户要求改为右侧宽抽屉。

抽屉顶部提供保存草稿、模拟测试和发布按钮；正文使用八步导航：

1. **基本信息：** 模板名称、编码、业务对象、业务阶段、待办类型、默认优先级、描述。
2. **触发事件：** 从事件目录选择事件，配置载荷版本和触发条件。
3. **负责人规则：** 配置 USER、ROLE、DEPT、POST、PAYLOAD、BUSINESS_OWNER、SUPERVISOR、ROUND_ROBIN、ASSIGNMENT_LEVEL，以及候选人、抄送、委托、跳过不可用人员和兜底规则。
4. **SLA规则：** 选择已启用 SLA 规则；允许在当前抽屉中以内嵌子抽屉新建规则，保存后自动回填。
5. **完成条件 DoD：** 多选已启用完成条件；允许以内嵌子抽屉新建完成条件，并配置组合方式。
6. **下一步触发：** 配置优先级、条件表达式、目标模板版本、默认分支和终止分支。
7. **预览测试：** 输入事件和 Payload，展示命中、Owner、SLA、DoD、路由和待办卡片预览。
8. **版本记录：** 展示草稿来源、历史发布版本、差异和回滚来源。

草稿可分步保存；发布前统一执行预检。任何子步骤失败时保留用户当前输入，并定位到失败步骤。

### 5.3 触发规则管理

对应参考图 5。

列表字段：规则名称、规则编码、来源事件、来源模板、条件摘要、目标动作、目标模板/流程、触发方式、状态、更新时间和操作。

抽屉支持新增、编辑、查看、复制、启停、排序和模拟触发。条件构建器复用现有条件表达式校验器；事件和 Payload 字段来自后端事件目录。启用规则必须引用已发布模板版本，停用规则不影响已经生成的待办。

### 5.4 SLA规则管理

对应参考图 3。

独立管理 SLA 名称、编码、类型、目标时长、时间单位、工作日历、起算策略、暂停策略、软提醒、硬提醒、升级节点、升级对象、自动动作和状态。

规则详情抽屉展示基础信息、80%/100%/150% 时间轴、计算示例、适用模板和版本引用。启停前检查绑定关系；停用只阻止新草稿选择，不改变已发布版本和历史待办快照。

### 5.5 完成条件管理

对应参考图 4。

独立管理规则名称、编码、规则类型、必填字段、必传附件、条件必填、外部校验器、错误提示、状态和绑定模板数。

抽屉采用分组折叠展示，支持字段类型、字段键、数量、文件类型、文件大小、条件表达式、校验能力和错误文案。测试规则时输入样例 Payload 和文件对象引用，返回逐项校验结果。

### 5.6 模拟测试

对应参考图 6。

左侧输入事件、业务对象类型、测试对象和 Payload；右侧按执行顺序展示状态变化、命中模板、Owner、SLA、DoD、下一步路由、待办卡片和执行日志。

模拟为只读行为，不写业务事实、不创建待办、不推进轮询游标。可从模板、触发规则、SLA 和 DoD 页面打开预填抽屉，也可从独立页面执行完整模拟。模拟记录仅保存输入摘要、定义版本、结果和耗时，不保存敏感业务正文。

### 5.7 发布记录

对应参考图 7。

发布记录由现有模板版本、定义动作账本和审计数据聚合生成，不维护第二套版本事实。

列表字段：模板、模板编码、版本号、发布状态、变更说明、影响范围、发布人、发布时间、回滚来源和操作。抽屉展示版本详情、变更摘要、语义差异、引用规则快照、影响范围、回滚来源和备注。

发布与回滚均生成审计动作。回滚实际创建基于历史版本的新草稿或新发布版本，不修改旧版本。

## 6. 数据模型

### 6.1 新增 `todo_sla_rule`

核心字段：

- `sla_rule_id`、`rule_code`、`rule_name`
- `sla_type`、`duration_value`、`duration_unit`
- `calendar_code`、`start_strategy`
- `soft_remind_percent`、`hard_remind_percent`、`escalate_percent`
- `pause_policy_json`、`escalation_policy_json`、`auto_action_json`
- `status`、`version`
- 创建、更新和审计字段

`rule_code` 唯一；比例满足 `0 < soft <= hard <= escalate`；规则被发布版本引用后仍可创建新修订，但不能原地改变历史快照。

### 6.2 新增 `todo_dod_rule`

核心字段：

- `dod_rule_id`、`rule_code`、`rule_name`、`rule_type`
- `required_fields_json`、`required_attachments_json`
- `conditional_rules_json`、`validator_refs_json`
- `error_messages_json`
- `status`、`version`
- 创建、更新和审计字段

字段键、附件类型和校验器必须通过能力目录或字典校验。规则编码唯一，更新采用乐观锁。

### 6.3 新增模板草稿绑定

新增草稿级引用表或等价持久化结构，记录模板草稿与触发规则、SLA规则、DoD规则、下一步规则之间的关系。模板发布时将这些引用编译进 `todo_template_version.definition_json`、`sla_rule_json`、`dod_rule_json` 和路由快照，运行时继续只依赖发布版本快照。

### 6.4 发布记录

发布记录使用以下现有事实聚合：

- `todo_template`
- `todo_template_version`
- `todo_definition_action`
- 发布预检和差异结果

不新增可与模板版本产生冲突的“发布记录主表”。如需保存发布说明和影响范围，仅对模板版本增加不可变发布元数据字段。

## 7. 字典初始化

通过一个新的前向 Flyway 迁移初始化以下字典类型及数据：

- `law_todo_business_stage`
- `law_todo_business_type`
- `law_todo_template_type`
- `law_todo_publish_status`
- `law_todo_trigger_mode`
- `law_todo_condition_operator`
- `law_todo_owner_rule_type`
- `law_todo_sla_type`
- `law_todo_sla_unit`
- `law_todo_sla_start_strategy`
- `law_todo_timeout_strategy`
- `law_todo_dod_rule_type`
- `law_todo_rule_status`
- `law_todo_version_status`

业务对象和业务阶段的具体值以仓库已确认的业务线和阶段为基线，后续只通过新增 Flyway 扩展。事件类型、处理器、校验器和自动动作属于运行时能力目录，不伪装成静态字典。

前端页面使用 `dicts`、`dict-tag` 和统一字典选择组件。后端写接口校验字典值处于启用状态，避免前端绕过。

## 8. 后端接口边界

保留现有模板、版本、预检、模拟、事件目录和触发规则接口，在其上增加面向新页面的分页查询与聚合详情。新增资源：

- `/todo/config/templates`
- `/todo/config/trigger-rules`
- `/todo/config/sla-rules`
- `/todo/config/dod-rules`
- `/todo/config/simulations`
- `/todo/config/release-records`

列表接口统一支持分页、关键字、字典筛选、状态和更新时间范围。写接口统一接收 `actionId`、`expectedVersion` 和强类型命令；重复 `actionId` 返回原结果或明确的幂等冲突，版本不一致返回可识别的并发错误码。

原 `/todo/template` 等接口保持兼容，直到新页面和已有业务抽屉全部切换并通过回归测试。

## 9. 错误处理和审计

1. 前端表单使用字段级错误、步骤级错误摘要和保存失败保留现场。
2. 后端为不存在、重复编码、非法字典值、并发冲突、规则被引用、预检失败和发布门禁失败提供稳定业务错误码。
3. 新建、编辑、复制、启停、模拟、发布、回滚和导入均记录操作审计。
4. 模拟不写业务事实；发布不允许绕过 Foundation 门禁。
5. 删除采用停用或逻辑删除；被草稿或发布版本引用的规则不能物理删除。

## 10. 组件边界

前端按职责拆分：

- `ConfigPageShell`：标题、指标、筛选、表格和分页骨架。
- `ConfigMetricCard`：统一指标卡。
- `ConfigDetailDrawer`：右侧抽屉容器、脏数据确认和固定底栏。
- `TemplateList`、`TemplateDrawer`、`TemplateStep*`：模板列表与八步配置。
- `TriggerRuleList`、`TriggerRuleDrawer`：触发规则。
- `SlaRuleList`、`SlaRuleDrawer`、`SlaTimeline`：SLA。
- `DodRuleList`、`DodRuleDrawer`：DoD。
- `SimulationWorkbench`、`SimulationResult`：模拟。
- `ReleaseRecordList`、`ReleaseRecordDrawer`、`VersionSemanticDiff`：发布记录。

单个页面容器只负责查询状态和抽屉协调；规则编辑、校验和摘要显示放在独立组件中。

## 12. 实施顺序

1. 菜单、权限、字典和数据库规则表。
2. SLA规则后端与页面。
3. 完成条件后端与页面。
4. 触发规则列表与抽屉重建。
5. 待办模板列表和八步配置抽屉。
6. 独立模拟测试页面。
7. 发布记录聚合与版本抽屉。
8. 移除旧配置中心入口和页面依赖。
9. 全量测试、真实MySQL、E2E和逐图视觉校验。

## 13. 明确不做

- 不删除 Foundation 治理表、接口、证据和发布守卫。
- 不修改待办运行时状态机和既有业务事实写入原则。
- 不引入新的前端框架、BPM 引擎、消息队列或微服务。
- 不在本轮实现短信、邮件、企业微信等外部通知渠道。
- 不以页面出现、Mock 数据或草稿存在作为发布完成证据。

## 14. 完成定义

只有同时满足以下条件才视为完成：

1. 六个独立菜单页面和模板八步抽屉全部可用。
2. 所有按钮操作均使用右侧抽屉，确认提示除外。
3. SLA 和 DoD 可独立管理、复用、启停、测试并正确生成发布快照。
4. 固定选项均来自已初始化字典或运行时能力目录。
5. 模板从草稿、模拟、预检、发布到发布记录形成真实闭环。
6. 现有 Foundation 门禁、25个PRD草稿和运行时Todo能力无回归。
7. 后端、前端、Flyway、真实 MySQL、浏览器 E2E 和视觉对比全部通过。
