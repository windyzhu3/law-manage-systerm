# TD-001 首联模板状态治理与模拟重新验证设计

> 状态：已于 2026-08-06 经用户确认采用方案 B。
> 代码基线：远程 `v0.2-Foundation` 对应代码树；本地运行工作区仅有启动配置和测试产物，不纳入本设计修改。
> 适用范围：待办配置工作台、TD-001 第七步模拟发布、线索首联历史模板及第六步后续路由布局。

## 1. 目标

本次修复解决三个相互关联的产品问题：

1. 将“模板配置是否完整”和“模板当前是否运行”分开表达，避免历史模板 `LEAD_FIRST_CONTACT` 与正式模板 `TD-001` 被误认为同时生效；
2. 允许对不可变的已发布版本重新执行纯模拟，从而在场景资源升级后生成新的有效证据；
3. 修正后续路由编辑器的响应式布局，避免中间效果卡和右侧下游模板下拉框重叠。

修复后不得修改已发布模板定义，不得伪造或迁移模拟通过证据，不得改变当前唯一生效的线索首联入口。

## 2. 已确认事实与根因

### 2.1 两张首联模板并未同时运行

当前运行库状态为：

- `LEAD_FIRST_CONTACT`，名称“线索首联”，模板状态为停用，`replacement_template_code=TD-001`；
- `TD-001`，名称“首联待办”，模板状态为启用；
- `LEAD_FIRST_CONTACT` 的三条 `LEAD_ASSIGNED` 触发规则全部停用；
- 唯一启用的入口槽为 `LEAD_FIRST_CONTACT_ENTRY`，目标模板为 `TD-001`。

冲突来自工作台投影而非运行时：工作台只返回七步配置进度和发布状态，没有返回模板运行状态、替代关系和锁版本，因此两张模板都显示为“7/7 已完成”。“已发布/配置完成”被用户自然理解为“当前生效”。

### 2.2 必测场景证据因场景版本升级而失效

TD-001 当前发布版本为版本 ID 88，定义哈希为：

```text
2a020ca6acd87f6a488e1545e17e54ee781c50d1c98ec16e23e135e161225e9a
```

三个受治理场景已升级到 `scenarioVersion=2`：

- `TD001_VALID`；
- `TD001_SUSPECT_INVALID`；
- `TD001_UNREACHABLE`。

现有通过证据属于 `scenarioVersion=1`。服务端按模板、版本、定义哈希、场景编码和场景版本共同校验，因此旧证据不应继续满足发布门禁。

服务端判断本身正确，但前端把“模板定义只读”和“模拟执行只读”绑定成同一状态：已发布版本不能加载测试对象、不能批量验证，也不能运行完整试运行。最终形成“系统要求重新验证，但页面禁止重新验证”的死锁。

### 2.3 路由布局存在确定性尺寸冲突

`BusinessRoutingEditor` 的三列布局为：

```text
minmax(200px, 1fr) 150px minmax(200px, 1fr)
```

中间效果卡同时设置了 `min-width: 220px`。子元素最小宽度大于其网格列 70px，在编辑区宽度受右侧健康面板挤压时必然覆盖第三列。

## 3. 产品决策

采用方案 B“完整治理闭环”。

### 3.1 模板存在四个独立状态维度

页面必须分别显示：

- 配置进度：七步完成数量；
- 版本状态：草稿、已发布、已退役版本；
- 运行状态：启用、停用；
- 替代关系：无替代或已由指定模板替代。

这些状态不得再合并成一个“配置完成”标签。

### 3.2 历史模板保留在默认列表

本设计覆盖 2026-07-31 设计中“默认隐藏退役模板”的展示约定。经本次确认：

- `LEAD_FIRST_CONTACT` 默认仍显示；
- 明确标记“已停用 · 已由首联待办（TD-001）替代”；
- 主操作为“打开现行模板”；
- 次操作为“查看历史配置”；
- 已设置替代关系的模板禁止重新启用；
- 历史版本、实例、动作和审计记录继续保留。

默认显示的目的不是让旧模板继续参与配置，而是让管理员看见替代事实，避免把历史资产误判为重复生效。

### 3.3 已发布定义只读，模拟执行可重复

不可变约束只作用于模板定义，不作用于纯模拟输入和验证证据：

- 事件、触发条件、负责人、DoD、SLA、路由和表单定义保持只读；
- 具有模拟权限的用户可以选择业务对象或加载只读样例；
- 可以修改本次模拟专用覆盖值；
- 可以运行单场景、全部必测场景和完整试运行；
- 模拟只追加证据和审计，不创建运行时待办、不写业务事实。

### 3.4 不补写或继承旧证据

场景版本升级后必须真实重跑。禁止通过 SQL 将版本 1 证据改成版本 2，禁止降低场景版本，也禁止将旧版本证据复制到当前版本。

## 4. 后端设计

### 4.1 扩展工作台投影

`TemplateWorkbenchItem` 增加：

```text
templateStatus
lockVersion
replacementTemplateCode
replacementTemplateId
replacementTemplateName
runtimeState
```

`runtimeState` 由服务端确定：

```text
ACTIVE    template_status = 0
REPLACED  template_status = 1 且 replacement_template_code 非空
INACTIVE  template_status = 1 且无替代模板
```

主操作由服务端返回稳定语义：

```text
OPEN_REPLACEMENT
CONTINUE_CONFIGURATION
VIEW_PUBLISHED
VIEW_HISTORY
```

前端不根据模板名称或编码猜测是否为历史模板。

### 4.2 复用模板启停服务

继续复用现有：

```text
POST /todo/config/templates/{id}/toggle
```

停用和启用必须携带：

- 目标状态；
- `expectedVersion`；
- 唯一 `actionId`。

已有服务端规则继续生效：存在 `replacement_template_code` 的模板不能重新启用。工作台只提供符合该规则的操作。

### 4.3 暴露权威模拟准入状态

`TodoConfigurationJourneyView` 增加 `simulationReadiness`，直接返回服务端统一投影：

```text
templateId
versionId
definitionHash
requiredScenarioCount
passedScenarioCount
blockingScenarios
fullSimulationPassed
publicationReady
issues
```

前端不得只从通用问题列表推测场景门禁。

### 4.4 识别场景版本升级

证据查询增加“同一模板版本、定义哈希和场景编码下的最新任意场景版本证据”。当当前场景版本没有通过证据时，按以下顺序返回原因：

```text
SCENARIO_UPDATED      存在旧场景版本证据，但场景版本已升级
DEFINITION_CHANGED    场景版本一致，但定义哈希不同
LAST_RUN_FAILED       当前版本最近一次运行失败
EVIDENCE_EXPIRED      当前版本通过证据已过期
MISSING               从未运行
```

`SCENARIO_UPDATED` 的用户提示为：

```text
测试场景规则已升级，原验证结果不再适用，请重新验证。
```

### 4.5 不改变运行时入口

本次不新增或切换入口槽，不自动激活 TD-001 新版本。当前唯一启用的 `LEAD_FIRST_CONTACT_ENTRY` 继续保留。模拟证据补齐后，是否切换到新的发布版本仍由现有“线索待办整体启用”流程控制。

## 5. 前端设计

### 5.1 工作台状态展示

工作台新增“运行状态”列：

- 启用：绿色标签“运行中”；
- 普通停用：灰色标签“已停用”；
- 已替代：灰色标签“已停用”，并显示“由首联待办（TD-001）替代”。

增加运行状态筛选：全部、运行中、已停用。

操作规则：

- 已替代模板：主操作“打开现行模板”，次操作“查看历史配置”；
- 启用模板：保留配置/查看操作，并在更多操作中提供“停用模板”；
- 未被替代的停用模板：提供“启用模板”；
- 点击启停操作前显示影响说明并要求确认。

### 5.2 已发布版本模拟模式

第七步顶部显示：

```text
当前为已发布不可变版本，配置不可修改；模拟验证仍可重新运行。
```

权限拆分为：

```text
canEditDefinition = !readonly && canEdit
canRunSimulation  = canSimulate
canPublishDraft   = !readonly && canPublish
```

业务对象选择、只读样例、场景输入、单场景验证、批量验证和完整试运行读取 `canRunSimulation`，不再读取 `canEditDefinition`。

### 5.3 一键重新验证

当必测场景或完整试运行失效时显示“一键重新验证”，执行：

```text
若未选择对象则加载只读样例
→ 载荷预检
→ 批量运行全部必测场景
→ 运行完整试运行
→ 重新获取 SimulationReadiness
→ 刷新健康度、步骤状态和整体启用资格
```

任一步失败即停止后续动作，并只显示一个主错误提示。单场景和分步操作仍保留，便于诊断。

### 5.4 场景失效反馈

场景门禁必须展示：

- 场景中文名称；
- 当前场景版本；
- 最近证据版本（如存在）；
- 阻塞原因中文说明；
- 可执行修复动作。

`TODO_REQUIRED_SIMULATION_SCENARIOS_INCOMPLETE` 仍是稳定总错误码，但不能成为唯一信息。

“去修复”定位到第一个阻塞场景并高亮“一键重新验证”区域，不能只滚动页面而不显示可执行操作。

### 5.5 后续路由响应式布局

三个控件增加明确类名：业务结果、系统效果、下游待办。

宽屏使用三列弹性布局，所有子项允许收缩且占满列宽；中等宽度切换为两列，下游待办独占下一行；窄屏切换为单列。

核心约束：

```text
中间效果卡 min-width: 0
所有 el-select width: 100%
网格子项 min-width: 0
不得使用“150px 列 + 220px 子项”组合
```

布局断点依据编辑器可用宽度和现有页面断点设置，不改变业务结果或路由序列化结构。

## 6. 失败处理与一致性

- 工作台启停并发冲突返回版本冲突，页面刷新该行后提示用户重试；
- 替代模板重新启用由服务端稳定拒绝，前端同时不提供该操作；
- 一键重新验证只在当前模板、版本和定义哈希完全匹配时接纳证据；
- 场景目录在运行中再次升级时，服务端返回版本冲突或新的 `SCENARIO_UPDATED`，页面不得显示成功；
- 批量场景通过但完整试运行失败时，已通过场景证据保留，健康度仍显示完整试运行阻塞；
- 页面刷新后必须从服务端恢复相同的运行状态和模拟准入结果。

## 7. 测试策略

### 7.1 后端单元测试

- 工作台返回 ACTIVE、INACTIVE、REPLACED 及替代模板信息；
- 已替代模板不能重新启用；
- 当前场景版本无证据、旧版本有证据时返回 `SCENARIO_UPDATED`；
- 当前版本失败、过期、定义变化和从未运行分别返回正确原因；
- Journey 返回与工作台一致的 `SimulationReadiness`。

### 7.2 Mapper 与 MySQL 集成测试

- `LEAD_FIRST_CONTACT` 为停用且替代模板为 TD-001；
- 只有 TD-001 占用 `LEAD_FIRST_CONTACT_ENTRY`；
- 场景版本 1 证据不能满足场景版本 2 门禁；
- 重跑后追加版本 2 证据，不修改版本 1 历史证据；
- 停用/启用使用乐观锁且不会绕过替代关系。

### 7.3 前端模型与组件测试

- 配置完成与运行状态分别渲染；
- 已替代模板主操作正确跳转 TD-001；
- 已发布版本仍可搜索对象、加载样例和运行模拟；
- 一键重新验证严格按顺序执行并在失败时停止；
- `SCENARIO_UPDATED` 显示中文解释；
- 路由三列、两列和单列布局无横向覆盖。

### 7.4 Playwright 真实验收

使用真实前后端与 MySQL：

1. 打开模板工作台，确认两张首联模板分别显示“运行中”和“已停用/已替代”；
2. 从“线索首联”点击“打开现行模板”，进入 TD-001；
3. 进入已发布 TD-001 第七步，确认配置只读但模拟控件可用；
4. 确认页面说明三个版本 2 场景使版本 1 证据失效；
5. 点击“一键重新验证”，确认三个场景和完整试运行全部通过；
6. 刷新页面，确认第七步和配置健康度保持通过；
7. 检查数据库只追加版本 2 模拟证据，业务表和运行时待办表不变；
8. 在常用桌面宽度和较窄宽度检查后续路由无重叠；
9. 检查浏览器控制台和后端日志无异常。

## 8. 验收标准

- 用户不会再把“7/7 配置完成”理解为模板正在运行；
- `LEAD_FIRST_CONTACT` 明确显示已停用、替代关系和历史入口；
- 当前唯一生效的首联入口仍指向 TD-001；
- 已发布 TD-001 能真实重跑版本 2 必测场景和完整试运行；
- 重跑后 `TODO_REQUIRED_SIMULATION_SCENARIOS_INCOMPLETE` 消失，页面刷新后不回退；
- 未真实执行的场景不得获得通过证据；
- 路由效果卡与下游待办选择器在支持的页面宽度下不重叠；
- 后端、前端、MySQL 集成和 Playwright 验收全部通过。

## 9. 非目标

- 不修改 TD-001 的业务定义和路由结果；
- 不重新设计 TD-002、TD-003、TD-004；
- 不切换线索发布包的当前运行版本；
- 不删除历史模板、历史版本或历史证据；
- 不升级 Vue、Element UI 或 RuoYi；
- 不修改已执行 Flyway 迁移。
