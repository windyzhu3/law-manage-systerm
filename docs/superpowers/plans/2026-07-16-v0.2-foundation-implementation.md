# v0.2 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `v0.2-Foundation` 分支完成可配置、可预检、可模拟、可运行的 Todo Engine 通用底座，以及正式 v0.2 开发所需的前端组件、后端能力和 TD-001～TD-025 准入清单。

**Architecture:** 以 `TodoDefinitionDocument` 作为配置端和运行端的唯一版本化契约，发布时编译为不可变运行快照；事件、Owner、DoD、SLA、路由、文件和通知分别通过小型领域服务组合。现有业务 Service 继续维护业务事实，Todo Completion Handler 只调用公开业务 Service。

**Tech Stack:** Java 17、Spring Boot 4.0.3、MyBatis Spring Boot 4.0.1、Fastjson2、Flyway、MySQL、Vue 2.6、Element UI 2.15、Playwright 1.52、Maven、Node.js。

## Global Constraints

- 开发分支固定为 `v0.2-Foundation`，基线提交为 `ea207d98`。
- 保持模块化单体，不引入微服务、MQ、通用 BPM、SpEL 或脚本表达式。
- 所有新增数据库变更从 `V0_20_1` 开始使用只增不改的 Flyway 迁移。
- 所有写 API 使用强类型 DTO、Bean Validation、功能权限、数据权限和 `actionId` 幂等。
- 已发布定义不可修改；新实例使用编译快照，历史实例不受后续版本影响。
- 未确认的 Q-001～Q-012 不设置技术臆测值，受影响定义保持 `BLOCKED` 且禁止发布。
- 先写失败测试，再写最小实现；每个任务独立提交并保持已有全量测试绿色。
- 前端运行表单不得按 `templateCode` 添加新分支；业务专用控件只能通过字段注册表扩展。
- 文件 API 使用 `fileObjectId`，新代码不得把裸 URL 当作可信文件凭证。
