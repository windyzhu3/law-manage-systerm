# 线索管理模块设计

## 1. 建设目标

线索管理是律所业务系统的前置入口，用于承接咨询、活动、转介绍等渠道产生的潜在客户信息，并持续记录分配、跟进、转化和回收过程。

第一阶段先建立清晰的菜单目录和页面骨架。后续实现时，线索模块应与客户、合同、案件模块解耦：线索转化后创建客户档案，但不直接创建合同或案件。

## 2. 菜单规划

| 菜单 | 路由 | 权限标识 | 主要使用角色 | 说明 |
| --- | --- | --- | --- | --- |
| 线索工作台 | `/lead/dashboard` | `lead:dashboard:view` | 销售、案源负责人、管理人员 | 展示待跟进、即将逾期、来源分布和转化漏斗 |
| 全部线索 | `/lead/all` | `lead:all:list` | 管理人员 | 管理全量线索，支持分配、转移、导入导出 |
| 我的线索 | `/lead/mine` | `lead:mine:list` | 销售、律师 | 处理本人负责的线索，记录跟进并发起转化 |
| 线索公海 | `/lead/pool` | `lead:pool:list` | 销售、案源负责人 | 管理未分配或被回收的线索，支持领取和分配 |
| 跟进任务 | `/lead/followup` | `lead:followup:list` | 销售、律师 | 查看待办、逾期任务和跟进记录 |
| 线索回收站 | `/lead/recycle` | `lead:recycle:list` | 管理人员 | 恢复误删线索或执行彻底删除 |
| 线索设置 | `/lead/settings` | `lead:settings:list` | 管理员 | 配置来源、标签、无效原因和公海规则 |

目录统一使用 `lead` 作为业务前缀。当前页面为规划骨架，不访问后端接口；后续按菜单逐项实现。

## 3. 核心状态

建议主表字段 `lead_status` 使用以下状态：

| 状态值 | 名称 | 进入条件 | 可执行动作 |
| --- | --- | --- | --- |
| `0` | 待分配 | 新增、导入或渠道接入 | 分配负责人、进入公海 |
| `1` | 待跟进 | 已明确负责人 | 创建跟进任务、记录联系结果 |
| `2` | 跟进中 | 已产生有效跟进记录 | 继续跟进、转移、判定无效、发起转化 |
| `3` | 已转化 | 已创建客户档案 | 查看关联客户 |
| `4` | 无效 | 重复、无法联系、明确拒绝等 | 重新激活、进入公海 |
| `5` | 已关闭 | 管理人员主动关闭 | 重新激活 |

线索是否进入公海建议使用独立字段 `pool_status`，不要混入主状态。删除使用 `del_flag` 软删除。

## 4. 数据模型

### 4.1 第一期表

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `biz_lead` | 线索主表 | 编号、名称、联系人、手机、来源、状态、负责人、部门、公海状态、下次跟进时间、转化客户 ID |
| `biz_lead_followup` | 跟进记录 | 线索 ID、跟进方式、跟进内容、结果、下次跟进时间、跟进人 |
| `biz_lead_assignment_log` | 分配轨迹 | 线索 ID、原负责人、新负责人、操作类型、操作原因、操作人 |
| `biz_lead_tag_rel` | 标签关联 | 线索 ID、标签 ID |
| `biz_lead_tag` | 标签配置 | 标签名称、颜色、启用状态 |

### 4.2 第二期扩展

| 表 | 用途 |
| --- | --- |
| `biz_lead_import_batch` | 导入批次、成功失败数量和错误文件 |
| `biz_lead_duplicate_rule` | 手机号、微信、企业名称等查重规则 |
| `biz_lead_pool_rule` | 超时回收、公海领取上限和保护期 |
| `biz_lead_source` | 渠道来源树和渠道成本配置 |

## 5. 关键规则

1. 手机号默认作为主要查重依据；重复线索允许提示后合并或补充跟进，不应静默覆盖。
2. 分配、转移、领取、回收必须记录轨迹，便于审计。
3. 普通人员只能查看本人线索；管理人员按部门数据权限查看。后端查询应复用 `@DataScope`。
4. 转化操作必须事务化：创建或绑定客户、回写线索状态、记录转化时间和操作日志。
5. 删除采用软删除；彻底删除仅允许管理员在回收站执行。
6. 公海规则与线索状态分离，避免后续统计和状态机混乱。

## 6. 推荐实施顺序

1. 建立 `biz_lead`、`biz_lead_followup`、`biz_lead_assignment_log` 表和业务字典。
2. 实现全部线索、我的线索、公海池三个核心列表。
3. 实现新增、编辑、详情、分配、转移、领取、回收和跟进记录。
4. 实现转客户流程，并与后续客户模块对接。
5. 补充回收站、设置、工作台统计和批量导入导出。
