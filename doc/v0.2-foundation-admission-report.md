## 4. 稳定行号策略

行号锚点是历史数据的一部分；兼容台账只允许在锚点含义不变的前提下维护。

- 第 105 行统一承载 G-04 四项 `NEEDS_EVIDENCE` 的完整语义。
- 第 109 行统一承载 G-05 PRD 材料链路的完整语义。
- 第 117 行统一承载 G-07 黄金数据与独立 Reviewer 的完整语义。

新增当前结论应写入规范报告，不应移动本文件锚点。

## 5. 消费方解释规则

读取历史 `source_ref` 时必须同时遵守以下规则：

1. 引用行存在且非空。
2. 引用行包含 gate、来源状态与所需证据。
3. 技术测试通过不自动把 `NEEDS_EVIDENCE` 改为 `CONFIRMED`。
4. 当前准入比例、数据库版本与门禁结果从规范报告读取。

## 6. 稳定证据锚点

以下内容按历史入站引用固定位置；自动化契约会验证行号和语义令牌。

### G-04 锚点

来源状态保持为 `NEEDS_EVIDENCE`，直至责任方提交并审批真实目标数据证据。

历史迁移的四项来源在同一锚点聚合，避免历史 checksum 因文档搬迁被改写。
G-04 `NEEDS_EVIDENCE`：提交无法自动分类案件的异常清单、回填批次与幂等方案、行数/枚举/关联/抽样校验 SQL，以及不破坏新增数据的回滚 SQL。

### G-05 锚点
来源状态保持为 `NEEDS_EVIDENCE`，技术文件服务覆盖不等于 PRD 材料业务验收。
G-05 `NEEDS_EVIDENCE`：以真实 PRD 材料类型完成上传、预览、下载和审计端到端证据，并交由安全责任方评审。

### G-07 锚点

来源状态保持为 `NEEDS_EVIDENCE`，Mock 隔离测试不抵扣阶段一验收。

黄金数据必须登记版本和校验和；评审身份必须与 Owner 和验收人分离。
独立评审结论必须可追溯到场景、AT 映射、责任人和验收记录。
G-07 `NEEDS_EVIDENCE`：提交版本化黄金数据及校验和，并由独立 Reviewer 完成阶段一验收评审；不得由 Owner 或验收人代签。
