# Todo Engine 业务可配置闭环验收评估

日期：2026-07-22
验收口径：以用户能否完成配置、发现问题并安全模拟为准，而不是仅检查接口或页面是否存在。

## 一、结论

当前 Todo Engine 已形成“事件目录 → 触发规则 → 模板 → 完成条件/SLA → 只读模拟”的技术闭环，核心能力可以进入业务资产补齐和体验收口阶段，但尚不建议直接宣布生产可用或开始大规模阶段二扩展。

| 范围 | 完成度 | 结论 |
|---|---:|---|
| 后端基础能力 | 88% | 事件、版本、触发、模板、预检、模拟、发布守卫已具备 |
| 前端配置能力 | 82% | 关键配置可操作，首次空数据创建缺陷已修复 |
| 默认业务资产 | 68% | 标准模板较完整，但 SLA/独立 DoD 规则为空，部分模板负责人解析失败 |
| 用户体验与高保真一致性 | 65% | 已从技术表单改为向导，但尚无仓库内权威高保真基线可完成像素级验收 |
| 综合完成度 | 80% | 可用于配置验证和业务试点，不宜直接判定阶段二准入通过 |

## 二、已验证能力

- 40 个待办模板、55 个模板版本，其中 30 个已发布。
- 32 条触发规则，其中 16 条启用。
- 36 个有效事件资源；每个事件具备业务对象、Payload Schema、字段说明和示例载荷。
- 36 个业务字段、15 类材料、5 个完成条件推荐配方。
- 5 个服务端校验器，前端以目录方式展示并可在完成条件中选择。
- 触发规则编辑时，Payload 字段下拉能够按事件版本动态展示字段。
- 完成条件使用“业务类型 → 推荐配方 → 必填字段/材料/校验器 → 高级条件”的向导模式。
- 模拟测试可选择真实业务对象；没有真实数据时提供明确标识且隔离的安全示例对象。
- 已完成一次真实只读模拟，预检与模拟接口均返回成功，并展示事件匹配、SLA、DoD、路由和卡片预览。
- 事件资源启用前会重新校验持久化 Schema 与示例 Payload，防止绕过保存期校验。
- 空列表时新增抽屉保持挂载，已覆盖模板、触发规则、SLA、完成条件和模拟测试页面。
- 新增迁移 `V0_20_39`，修复错误初始化数据库中显示为问号的导航菜单；全新 v0.15 基线至 0.20.39 的真实 MySQL 迁移测试通过。

## 三、仍未达到阶段二准入的项目

### P0：业务资产闭环

1. 当前 `todo_sla_rule` 与 `todo_dod_rule` 均无默认规则。应按 v0.2 主链路建立可复用 SLA 与 DoD 规则，并绑定标准模板。
2. 已发布“线索首联”模板模拟结果中负责人解析为 `UNRESOLVED`。应逐一模拟 30 个已发布版本，修复负责人、候选池和兜底策略。
3. 模拟页同时展示未通过预检的草稿模板；用户点击后仅收到通用错误。应在列表直接显示预检状态，并在抽屉内展示具体错误和修复入口。
4. 16 条未启用触发规则需要明确是待发布资产、停用资产还是配置不完整，不能只保留技术状态。

### P1：用户体验收口

1. 建立“配置向导首页”，按业务顺序串联事件、模板、触发、SLA、DoD 和模拟，避免用户在七个菜单间自行理解依赖关系。
2. 事件代码、版本 ID、定义哈希等技术信息默认折叠；业务名称、用途、影响范围和修复建议前置。
3. 校验器目录不允许业务用户创建任意服务端代码，但应支持维护显示名称、用途、适用范围、启停状态和引用关系。
4. 完成条件配方应覆盖合同审批、缴费、分案、接案、节点办理、结案和归档，不只提供少量基础配方。
5. 建立权威高保真页面清单与逐页截图验收；当前仓库没有足以证明像素级一致性的设计源文件，因此不能宣称高保真验收通过。

### P1：运维与质量

1. 统一数据库初始化入口，强制 MySQL 客户端使用 `utf8mb4`，避免菜单、用户和部门基础数据被写成问号。
2. 发布前批量执行“全部已发布模板 × 对应事件 × 安全测试对象”的模拟回归，并将负责人未解析、预检失败作为阻断项。
3. 为配置资源、空状态新增、Payload 下拉、DoD 向导和模拟对象选择建立浏览器自动化回归。

## 四、阶段二准入标准

- SLA 与 DoD 默认规则覆盖 v0.2 主链路，且标准模板均完成绑定。
- 30 个已发布模板批量模拟无 `UNRESOLVED` 负责人、无预检错误。
- 草稿模板预检问题可在页面直接定位并跳转修复。
- 权威高保真页面逐页验收通过，关键任务不要求用户手填 JSON、ID 或技术编码。
- 全新数据库初始化、Flyway 升级、后端测试、前端构建和浏览器回归全部通过。
