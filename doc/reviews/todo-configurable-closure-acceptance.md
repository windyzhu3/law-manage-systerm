# Todo Engine 业务可配置闭环验收评估

阶段一“业务可配置闭环”通过技术验收，具备进入阶段二 PRD 业务实现的基础；这不等同于生产准入，也不代表高保真视觉验收已经完成。

| 前端配置能力 | 90% | 核心配置可操作，批量诊断、结构化预检与修复入口可用 |

| 阶段一综合完成度 | 92% | 阶段一通过，可进入阶段二；生产准入仍需业务场景、权限和高保真验收 |

## 二、阶段一已验收能力

- 36 个启用事件资源，均具备业务对象、Payload Schema、字段说明和示例载荷。
- 触发规则编辑时，Payload 字段下拉按事件版本动态生成；事件资源具备独立维护页面。
- 36 个业务字段、15 类材料、5 个完成条件推荐配方和 5 个服务端校验器可在配置页面选择。
- 完成条件采用“推荐配方 → 必填字段/材料/校验器 → 高级条件”配置方式，减少直接填写技术 JSON。
- 4 个可复用 SLA、15 个语义化 DoD、15 个当前发布技术模板和 16 条启用触发规则已完成绑定。
- 模拟测试只展示当前发布模板，支持真实业务对象、安全示例对象和“一键检查全部发布配置”。
- 批量诊断真实接口结果：总数 15，通过 15，告警 0，失败 0。
- 负责人规则已接入真实 RuoYi 用户、角色、部门和岗位目录；定义模拟允许安全示例 ID，生产执行仍校验账号可用性。
- 草稿打开时自动执行发布前检查，并按配置阶段展示问题、诊断码和“去修复”入口。
- Flyway 运行期自动配置已补齐；应用启动可将数据库自动升级到 0.20.41。
- `CASE_ACCEPT` 以新不可变版本修正负责人字段为事件目录中的 `lawyerId`，旧发布快照保留为退役版本。
- 本地环境显式启用后生成 6 个隔离测试部门、12 个测试用户和精确角色关系；生产环境不会创建测试身份。
- 全新 v0.15 基线至 0.20.41 的真实 MySQL 迁移和数据库不变量验证通过。

## 三、阶段二实施时继续优化的项目

### 用户体验与高保真

1. 以权威高保真设计源建立页面清单、组件映射和逐页截图差异验收，当前不能宣称像素级一致。
2. 建立面向业务用户的配置向导首页，将事件、模板、触发、SLA、DoD 和模拟串成推荐任务路径。
3. 默认折叠事件代码、版本 ID、定义哈希等技术信息，优先呈现业务名称、用途、影响范围和修复建议。
4. 扩充完成条件配方，覆盖 v0.2 的合同审批、缴费、分案、接案、节点办理、结案和归档场景。

### PRD 业务资产

1. `TD-001` 至 `TD-025` 仍按治理规则保持 `BLOCKED` 草稿；阶段二应逐个补齐业务事件、处理器、字段和决策后发布，不能用技术模板数量替代 PRD 覆盖率。
2. 每完成一个 PRD 场景，必须加入“模板 × 事件样例 × 测试对象”的批量模拟回归。
3. 负责人规则中的 `BUSINESS_OWNER`、`SUPERVISOR`、`ROUND_ROBIN`、委托和分派层级在被具体 PRD 场景采用前，需补齐持久化适配与专项验收。

### 工程质量

1. 增加配置资源、Payload 下拉、DoD 向导、预检修复和模拟对象选择的浏览器自动化回归。
2. 优化前端包体；当前生产构建通过，但仍有既有 bundle-size 警告。
3. 阶段二每批变更继续执行全量 Maven 测试、真实 MySQL Flyway 门禁、前端 UTF-8/契约检查和生产构建。

## 四、阶段二准入结论

- 技术准入：**通过**。
- PRD 业务覆盖：**作为阶段二实施内容，不计入阶段一完成项**。
- 生产准入：**未通过**，需完成真实业务场景、权限、高保真、浏览器回归和独立验收。
